# occasion-ops

OccasionOps 是一款面向红白事、节日、祭典、演出、庆典、宗族活动及其他临时组织活动的事务与资源管理系统。

项目主要解决活动筹备和执行过程中，采购、资金、物料、人力、任务、场地、施工、装饰、供应商及现场交接等事务分散、记录混乱、责任不清和事后难以整理的问题。

«適用於儀式、節慶、表演、社區活動、婚禮、葬禮和其他臨時組織的活動的輕量級操作和資源管理系統。»

项目背景

红白事、节日祭典、演出庆典等活动，通常具有以下特点：

- 筹备时间短，临时变化多；
- 参与人员多，职责经常临时调整；
- 采购、付款、收款和物料可能经过多人之手；
- 活动资金分散在多个账户、现金保管人和临时资金池中；
- 现场人员需要不断走动，难以进行复杂的手机操作；
- 大量事务通过口头、电话、微信和纸质单据临时记录；
- 活动结束后，需要重新整理礼金、费用、垫付款、物料和人员交接情况。

传统记账软件只能记录简单的收入和支出，普通项目管理软件又往往不适合临时活动现场使用。

OccasionOps 希望将一场活动中发生的各种事项，统一整理为可记录、可关联、可核对、可追溯的活动流水。

项目目标

OccasionOps 的目标是让活动负责人能够随时回答以下问题：

1. 钱从哪里来？
2. 钱现在在哪里？
3. 钱最终花到哪里？
4. 谁垫付了费用，是否已经报销？
5. 物料买了多少，现在在哪里？
6. 哪些物品需要归还？
7. 每件事情由谁负责？
8. 哪些任务、款项和交接仍未完成？
9. 某项决定是谁在什么时候作出的？
10. 活动结束后，如何快速生成完整汇总？

适用场景

OccasionOps 不限定于某一种活动类型，可用于：

- 婚礼、寿宴等红事；
- 丧礼、追悼、祭扫等白事；
- 节日、庙会、祭典及民俗活动；
- 演出、晚会、庆典和展演活动；
- 宗族、社区、村镇和公益活动；
- 临时宴席和大型聚会；
- 其他需要多人协作、资金管理和现场执行的活动。

- 微信、支付宝、银行卡和现金等多种支付方式；

- 内部资金转移和现金交接；
- 个人垫付、备用金、报销和余款退回；
- 商家订金、尾款、押金和退款；
- 应收、应付和未结算事项。

采购与供应商

- 采购需求；
- 询价和报价；
- 采购审批；
- 下单、订金和尾款；
- 到货验收；
- 临时增购和变更；
- 退货和退款；
- 商家服务履约和异常记录。

- 租赁物品管理；
- 消耗、剩余和盘点；
- 损坏、遗失和处置；
- 物料当前位置和保管人。

人员与任务

- 活动成员和临时参与人员；
- 负责人、协助人和联系人；
- 任务创建、分派和接收；

活动流水与证据

产品设计原则

1. 现场操作优先

系统首先服务于正在活动现场奔走的人员，而不是坐在办公室中的专业财务人员。

常用操作应尽量在数秒内完成。

2. 使用生活化语言

前台不要求用户理解会计、仓储或项目管理术语。

例如：

- 收到一笔；
- 花了一笔；
- 我先垫付；
- 钱交给别人了；
- 东西到了；
- 有人领走了；
- 这件事交给他；
- 商家还没来；
- 这个钱还没付。

系统在后台再将这些操作转换为标准化流水。

3. 允许不完整记录

现场人员可以先记录金额、照片、语音或一句简单说明，稍后再由负责人补充和确认。

不能因为信息不完整而阻止用户记录。

4. 原始资料必须保留

AI识别结果、人工整理结果和原始资料必须分别保留。

图片、票据、截图、语音和原始记录不能因后续整理而丢失。

5. 重要数据可追溯

涉及资金、礼金、库存和责任的记录，不应直接无痕删除。

修改、作废和更正都应保留历史记录。

6. 适配不同使用人群

系统需要考虑：

- 老年用户；
- 不熟悉智能手机的用户；
- 临时参与人员；
- 方言和普通话混合输入；
- 单手操作；
- 户外强光和嘈杂环境；
- 网络不稳定；
- 不愿安装应用的临时人员。

核心操作入口

初版计划围绕以下几个高频入口设计：

- 收到一笔；
- 花了一笔；
- 转交一笔；
- 有人垫付；
- 物料进出；
- 安排事情；
- 拍照记录；
- 语音记录；
- 待确认事项；
- 未完成事项。

不同角色可以看到不同的快捷入口。

主要角色

系统初步考虑支持以下角色：

- 活动总负责人；
- 家属负责人；
- 理事会成员；
- 管账人员；
- 收礼人员；
- 采购人员；
- 物料管理员；
- 场地和施工负责人；
- 任务负责人；
- 临时帮工；
- 外部供应商；
- 审核和查看人员。

角色权限不仅需要限制功能，还需要限制可查看的数据范围。

例如，临时采购人员可以提交自己的采购和垫付记录，但不一定能够查看全部礼金和活动资金。

AI能力规划

OccasionOps 计划逐步引入AI辅助能力，包括：

- 将语音描述整理为结构化流水；
- 从票据、截图和照片中识别金额、时间和商家；
- 自动识别垫付款和对应报销；
- 自动识别重复记录；
- 自动关联内部转账和现金交接；
- 自动拆解复杂描述中的多条流水；
- 自动发现未报销、未交账和未归还事项；
- 自动检查资金和物料是否闭环；
- 自动生成每日简报和活动总结；
- 支持使用自然语言查询活动情况。

AI只负责辅助整理和发现问题，重要数据仍需由相关人员确认。

初版范围

第一阶段计划优先完成以下四个闭环。

1. 资金闭环

- 活动收入；
- 多账户和现金箱；
- 内部转账；
- 现金交接；
- 资金余额；
- 资金归集。

2. 支出闭环

- 活动支出；
- 个人垫付；
- 备用金；
- 报销；
- 余款退回；
- 商家结算。

3. 物料闭环

- 采购；
- 到货；
- 入库；
- 领用；
- 调拨；
- 剩余；
- 归还。

4. 任务闭环

- 创建任务；
- 指定负责人；
- 执行反馈；
- 临时转交；
- 完成确认；
- 异常和超时。

项目状态

OccasionOps 当前处于需求整理和产品设计阶段。

目前主要工作包括：

- 梳理活动中的操作流水；
- 设计资金、物料、任务和人员之间的关系；
- 设计适合现场使用的低门槛交互；
- 确定第一阶段最小可用版本；
- 设计AI自动整理和人工确认机制。

项目尚未进入稳定版本，不建议直接用于真实活动中的正式财务管理。
