# OccasionOps 领域术语表

> 对应 [Issue #1](https://github.com/Ltre/occasion-ops/issues/1)。本文定义产品、数据模型、API 和测试共同使用的首版术语。地区性称呼可以作为别名展示，但不得改变术语的业务含义。

## 1. 使用规则

- 一个术语只表达一种业务含义；同义口语在界面层映射到标准术语。
- 记录人、实际执行人、责任人必须分开表达，不以“操作人”混称。
- 原始事实、AI 候选和人工确认结果分别保存，不互相覆盖。
- 资金、物料和责任均可具有当前位置；“发生过”不等于“现在仍在”。
- 重要记录采用追加、更正、作废，不做无痕修改或物理删除。

## 2. 平台与组织

| 术语 | 英文标识 | 定义 | 不包括 |
| --- | --- | --- | --- |
| 活动 | `Occasion` | 一次有明确目的、参与者和生命周期的临时组织事务，是首期数据隔离边界。 | 长期企业组织本身 |
| 活动阶段 | `OccasionPhase` | 活动在筹备、执行、收尾、结算、归档中的当前阶段。 | 单条任务的状态 |
| 参与者 | `Party` | 流水中涉及的个人、家庭、单位、工作组、商家或其他可识别主体。 | 必须拥有账号的假设 |
| 活动成员 | `Member` | 已加入活动并具有成员身份的参与者。 | 仅被记录的付款人或联系人 |
| 临时参与者 | `TemporaryParticipant` | 通过受限链接、二维码或代理录入参与指定事项、但不具备完整成员身份的人。 | 默认读取全活动数据的访客 |
| 角色 | `Role` | 在某一活动内授予的一组职责与功能权限，可叠加。 | 永久全局身份 |
| 数据范围 | `DataScope` | 角色在本人、工作组、区域、资金位置或事项类型上的可见和可操作边界。 | 单纯页面菜单可见性 |
| 商家 | `Vendor` | 提供商品、租赁、施工或服务并参与订单和结算的外部主体。 | 默认视为活动成员 |

## 3. 统一流水基础

| 术语 | 英文标识 | 定义 |
| --- | --- | --- |
| 流水 | `FlowRecord` | 对一次有业务意义的事实、状态变化或资源移动的结构化记录。流水是事实载体，不等同于会计凭证。 |
| 流水类型 | `FlowType` | 描述流水发生了什么的稳定分类，例如外部收入、内部转移、物料调拨、任务转交。 |
| 主体 | `Subject` | 流水主要描述的人、组织、订单、物料批次、任务或其他对象。 |
| 资源 | `Resource` | 可被持有、使用、移动或结算的资金、物料、设备、钥匙、车辆使用权等。 |
| 位置 | `Location` | 资源当前所在或由谁保管的可识别节点，包括账户、现金箱、人员、区域、仓库、车辆、商家和在途位置。 |
| 来源位置 | `SourceLocation` | 本次移动前资源所在位置；无来源时必须由流水类型明确允许。 |
| 目标位置 | `TargetLocation` | 本次移动后资源所在位置；无目标时必须由流水类型明确允许。 |
| 记录人 | `Recorder` | 将信息录入系统的人。 |
| 实际执行人 | `Actor` | 在现实中完成收款、付款、采购、收货、交接等动作的人。 |
| 责任人 | `Assignee` | 对事项后续推进或结果负责的人，可与记录人和实际执行人不同。 |
| 实际发生时间 | `OccurredAt` | 现实动作发生的时间。 |
| 记录时间 | `RecordedAt` | 系统接收并保存记录的时间。 |
| 原始输入 | `SourceInput` | 用户提交的原话、图片、语音、票据、截图或导入行。 |
| 附件 | `Attachment` | 与流水或对象关联的文件载体。 |
| 证据 | `Evidence` | 被用于支持事实确认、验收、更正或争议处理的附件或说明；附件不当然构成证据。 |
| 关联 | `Relation` | 两条流水或两个领域对象之间有类型、有方向、可审计的联系。 |
| 待整理记录 | `InboxRecord` | 已保留原始事实，但结构化字段尚未补齐的记录。 |
| AI 候选 | `AICandidate` | AI 从原始输入推断出的候选字段、候选流水或候选关联，尚不是已确认事实。 |
| 人工确认 | `HumanConfirmation` | 有权限的人对候选或待确认事实作出的明确确认。 |
| 更正 | `Correction` | 以新记录修正已存在记录，并保留原值、原因、操作者和时间。 |
| 作废 | `Void` | 声明一条记录不再参与有效业务计算，但仍永久保留其历史。 |
| 审计事件 | `AuditEvent` | 对创建、查看敏感数据、确认、更正、作废、授权等操作的不可无痕覆盖记录。 |

## 4. 资金、礼金与结算

| 术语 | 英文标识 | 唯一定义 |
| --- | --- | --- |
| 资金位置 | `MoneyLocation` | 活动相关资金在某一时点所在的账户、现金箱、个人、商家占用或在途节点。个人账户只计算活动相关子余额。 |
| 外部收入 | `ExternalIncome` | 资金从活动体系外进入活动体系并增加活动权益，例如礼金、赞助、补贴。退款必须作为原交易的反向结算标识，不与一般收入混淆。 |
| 对外支出 | `ExternalExpense` | 活动承担经济责任，资源流向活动体系外并形成真实成本。 |
| 内部转移 | `InternalTransfer` | 资金在活动相关位置之间移动，只改变位置余额，不改变活动净收支。 |
| 提现 | `CashWithdrawal` | 同一资金所有权下由非现金位置转至现金位置的内部转移。 |
| 换现 | `CashExchange` | 通过他人或机构将支付账户资金换为现金、或反向兑换的内部转移；手续费另记对外支出。 |
| 现金交接 | `CashHandover` | 现金在保管人或现金箱之间转移的内部转移，可要求双方确认。 |
| 资金归集 | `FundConsolidation` | 将分散资金集中到指定位置的一组内部转移。 |
| 个人垫付 | `PersonalAdvance` | 个人先以非活动资金支付活动应承担的费用，同时产生对外支出和活动对该人的待偿义务。 |
| 报销 | `Reimbursement` | 活动资金向垫付人偿还待偿义务；它结清债务，不再次形成活动成本。 |
| 备用金 | `PettyCashAdvance` | 活动资金预先交给经办人、供限定用途使用并须交账或退回余款的资金。 |
| 余款退回 | `UnusedFundReturn` | 经办人将未使用的备用金退回活动资金位置，属于内部转移。 |
| 订金/预付款 | `DepositPayment` | 为订单履约预先支付并冲抵应付金额的款项。法律性质由具体约定记录，不在系统术语中自动推定“定金”。 |
| 押金 | `SecurityDeposit` | 为履约或物品完好暂由对方占用、原则上可退的资金，不在支付时直接计为成本。 |
| 尾款 | `FinalPayment` | 在已支付部分款项后用于结清订单应付的后续付款。 |
| 退款 | `Refund` | 外部主体返还原付款的全部或部分金额，必须关联原付款、订单或押金事项。 |
| 盘点 | `ReconciliationCount` | 在指定时点记录某资金位置的实际金额并与理论余额比较。 |
| 盘点差异 | `BalanceVariance` | 实际盘点金额与系统理论余额之差；差异本身不是收入或支出，需说明、补记或更正。 |
| 礼金主体 | `GiftAttributionParty` | 礼金表达所归属的个人、家庭、单位或关系群体。 |
| 实际付款人 | `Payer` | 实际提供付款资金的人或单位，可与礼金主体不同。 |
| 代收人 | `Collector` | 代表活动或礼金接收方暂时收取款项的人。 |
| 转交人 | `Transferor` | 将已代收或保管资金转至下一位置的人。 |
| 礼金分配 | `GiftAllocation` | 实际付款与一个或多个礼金主体之间的金额归属关系，不代表新的资金移动。 |

## 5. 采购、物料与供应商

| 术语 | 英文标识 | 唯一定义 |
| --- | --- | --- |
| 采购需求 | `PurchaseRequest` | 对所需物料或服务、用途、数量、期限和责任的请求；不等于已下单。 |
| 确认/批准 | `Approval` | 有权限的人确认某项需求、变更或超额行为可继续；它不等于实际执行。 |
| 报价 | `Quote` | 商家在一定条件和有效期内提出的价格及交付条件。 |
| 采购订单 | `PurchaseOrder` | 活动与选定商家之间的采购承诺，可来源于合同、聊天或口头约定。 |
| 订单项 | `OrderLine` | 订单中具有独立品名、规格、数量、单价或交付状态的项目。 |
| 收货 | `Receipt` | 现实中已接收到商品或材料的事实，不自动表示数量、规格或质量合格。 |
| 验收 | `Acceptance` | 有权限的人对数量、规格、质量或服务结果是否符合要求作出的确认。 |
| 物料 | `Material` | 活动中被采购、借入、租赁、保管、使用或处置的实物资源。 |
| 物料批次 | `MaterialBatch` | 来源、规格、取得时间或成本相同而需要共同追踪的一组物料。 |
| 物料实例 | `MaterialInstance` | 需要逐件追踪、归还或记录损坏的单个物品。 |
| 入库 | `StockIn` | 物料进入某个可管理位置并计入该位置数量。可直接进入使用点，不强制中央仓库。 |
| 领用 | `IssueForUse` | 物料从保管位置交给人员、任务或使用区域，可能仍属于活动可追踪资源。 |
| 调拨 | `StockTransfer` | 物料在活动内部位置之间移动，不改变活动总量。 |
| 消耗 | `Consumption` | 物料因实际使用而不再可用，减少可用总量。 |
| 退回 | `ReturnToStock` | 未使用物料从领用位置回到可用库存位置。 |
| 退货 | `ReturnToVendor` | 物料退回外部商家，后续退款或抵扣须单独关联。 |
| 借入 | `BorrowIn` | 活动暂时取得他人物品使用权并负有归还义务。 |
| 租赁 | `Rental` | 活动以费用换取物品在约定期间的使用权并负有归还义务。 |
| 归还 | `ReturnBorrowedItem` | 借入或租赁物交回权利人的事实。 |
| 处置 | `Disposition` | 对剩余或不可用物料作出赠送、出售、保留、报废等最终处理。 |

## 6. 人员、任务、场地与交接

| 术语 | 英文标识 | 唯一定义 |
| --- | --- | --- |
| 任务 | `Task` | 有目标、责任人、状态和可验证结果的待办事项，可关联资金、物料、区域、车辆或商家。 |
| 负责人 | `Owner` | 对任务推进和结果负责的人。 |
| 协助人 | `Collaborator` | 参与执行但不取代负责人责任的人。 |
| 任务转交 | `TaskHandover` | 将任务责任从原负责人交给新负责人，并保留进度、资源、风险和双方确认的流水。 |
| 资源交接 | `ResourceHandover` | 资金、物料、钥匙、设备、车辆等保管责任从一方转至另一方的流水。 |
| 班次 | `Shift` | 在明确起止时间和区域内的一段值班责任安排。 |
| 区域 | `Area` | 活动场地中可分配负责人、任务、物料和风险的管理单元。 |
| 完成 | `Completed` | 执行人声明任务工作已做完；不自动代表结果被验收。 |
| 验收通过 | `Accepted` | 有验收权限的人确认任务、施工、服务或到货符合要求。 |
| 阻塞 | `Blocked` | 任务因等待资源、他人、审批或异常而暂时无法推进。 |
| 临时变更 | `ChangeRequest` | 对采购、施工、任务或预算的现场调整要求，须保留提出人、确认人、影响和依据。 |

## 7. 必须保持的边界

1. 礼金主体不等于实际付款人；礼金分配不等于资金移动。
2. 内部转移不等于收入或支出；报销不等于再次支出。
3. 收货不等于验收；任务完成不等于验收通过。
4. 记录人不等于实际执行人；实际执行人不等于责任人。
5. 附件不当然是证据；AI 候选不等于确认事实。
6. 盘点差异不自动计入损益；必须通过说明、补记、更正或责任处理闭环。

## 8. 待确认项

- 多币种、金额舍入和最小货币单位规则；
- “订金”与具有特定法律后果的“定金”在界面上的地区化提示；
- 现金交接、任务转交和验收需要双方确认的金额或事项阈值；
- 散装物料单位换算与估算数量的确认规则；
- 礼金主体在个人、家庭、单位和关系群体之间的默认选择；
- 活动、子活动和多个独立理事会之间的数据隔离方式。
