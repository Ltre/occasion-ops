# OccasionOps 流水类型词典

> 对应 [Issue #1](https://github.com/Ltre/occasion-ops/issues/1)。类型标识为首版概念编码；进入数据库迁移前仍可在 ADR 中调整命名，但业务含义不可静默改变。

## 1. 公共规则

每条流水至少包含：`occasionId`、`type`、`occurredAt`、`recordedAt`、`recorder`、`actor`、`status`、来源渠道和幂等键。涉及资源移动时还须包含来源位置、目标位置、金额或数量及单位。

- 同一现实动作只生成一条主事实流水；由该动作产生的债务、状态或资源变化通过关联表达。
- 需要双边平衡的移动不得拆成互不关联的两条单边记录。
- `source = target` 的资源移动无效。
- 不允许以负金额或负数量表示反向业务；使用明确的反向类型并关联原记录。
- AI 只能创建候选流水，确认后才进入正式投影。

## 2. 资金流水

| 类型 | 编码 | 来源 → 目标 | 影响净收支 | 关键约束 |
| --- | --- | --- | --- | --- |
| 外部收入 | `MONEY_EXTERNAL_IN` | 活动外 → 资金位置 | 增加收入 | 必须说明收入性质；退款不使用此类型 |
| 对外支出 | `MONEY_EXTERNAL_OUT` | 资金位置或个人资金 → 活动外 | 增加支出 | 垫付时须关联垫付义务 |
| 内部资金转移 | `MONEY_INTERNAL_TRANSFER` | 资金位置 → 资金位置 | 不影响 | 原子性更新两端位置 |
| 提现 | `MONEY_CASH_WITHDRAWAL` | 支付账户 → 现金位置 | 不影响 | 手续费另记对外支出 |
| 换现 | `MONEY_CASH_EXCHANGE` | 一种资金位置 → 另一资金位置 | 不影响 | 记录经办人与差额原因 |
| 现金交接 | `MONEY_CASH_HANDOVER` | 保管人/现金箱 → 保管人/现金箱 | 不影响 | 可进入待对方确认 |
| 资金归集 | `MONEY_CONSOLIDATION` | 分散位置 → 归集位置 | 不影响 | 每个来源分别可追溯 |
| 个人垫付 | `MONEY_PERSONAL_ADVANCE` | 个人资金 → 活动外 | 增加支出 | 同时建立待偿余额 |
| 报销 | `MONEY_REIMBURSEMENT` | 活动资金 → 垫付人 | 不影响 | 不得超过所关联待偿余额 |
| 备用金发放 | `MONEY_PETTY_CASH_ISSUE` | 活动资金 → 经办人位置 | 不影响 | 记录用途、领款人和待交账余额 |
| 备用金余款退回 | `MONEY_PETTY_CASH_RETURN` | 经办人位置 → 活动资金 | 不影响 | 关联原发放记录 |
| 订金/预付款 | `MONEY_DEPOSIT_PAYMENT` | 活动或个人资金 → 商家占用位置 | 依订单归集成本 | 关联订单与应付 |
| 押金支付 | `MONEY_SECURITY_DEPOSIT_OUT` | 活动或个人资金 → 商家占用位置 | 不直接计成本 | 建立待退押金 |
| 押金退回 | `MONEY_SECURITY_DEPOSIT_RETURN` | 商家占用位置 → 资金位置 | 不影响 | 关联原押金；扣除部分另行确认成本 |
| 尾款支付 | `MONEY_FINAL_PAYMENT` | 活动或个人资金 → 商家 | 依订单归集成本 | 不得无依据超过剩余应付 |
| 退款入账 | `MONEY_REFUND_IN` | 商家/外部 → 资金位置 | 冲减原成本或应收 | 必须关联原付款或订单 |
| 资金盘点 | `MONEY_COUNT` | 无移动 | 不影响 | 保存理论值、实际值和差异 |
| 资金差异处理 | `MONEY_VARIANCE_RESOLUTION` | 依处理方案 | 依确认结果 | 不允许由盘点自动生成收支 |

## 3. 礼金流水

| 类型 | 编码 | 定义 | 关键约束 |
| --- | --- | --- | --- |
| 礼金表达登记 | `GIFT_ATTRIBUTION_RECORDED` | 登记礼金主体、表达方式及备注 | 不改变资金余额 |
| 礼金实际收款 | `GIFT_PAYMENT_RECEIVED` | 登记付款人、金额、方式和到账位置 | 同时属于外部收入事实，不重复累计 |
| 礼金款代收 | `GIFT_COLLECTED` | 记录代收人取得保管责任 | 必须指向实际资金位置 |
| 礼金款转交 | `GIFT_HANDED_OVER` | 代收位置转至下一资金位置 | 属于内部资金转移 |
| 礼金分配 | `GIFT_PAYMENT_ALLOCATED` | 将一笔或多笔付款金额分配给礼金主体 | 分配合计不得超过已确认付款；不移动资金 |
| 礼金归属待确认 | `GIFT_ATTRIBUTION_PENDING` | 金额、付款人或礼金主体尚不完整 | 保留原始输入和待确认原因 |

## 4. 采购与商家流水

| 类型 | 编码 | 定义 |
| --- | --- | --- |
| 提出采购需求 | `PROCUREMENT_REQUESTED` | 建立物料或服务需求、用途和期望时间 |
| 确认采购需求 | `PROCUREMENT_APPROVED` | 有权限的人确认继续采购；先买后补可事后关联 |
| 记录报价 | `PROCUREMENT_QUOTED` | 保存商家报价及条件 |
| 创建采购订单 | `PROCUREMENT_ORDERED` | 记录最终采购承诺及订单项 |
| 采购变更 | `PROCUREMENT_CHANGED` | 记录增项、减项、替换、价格或交期变化 |
| 商家到场 | `VENDOR_ARRIVED` | 记录服务商或施工人员到场事实 |
| 收货 | `PROCUREMENT_RECEIVED` | 记录全部或部分商品到达及收货人 |
| 到货验收 | `PROCUREMENT_ACCEPTED` | 对数量、规格和质量作出验收结论 |
| 退货 | `PROCUREMENT_RETURNED` | 商品从活动位置退给商家 |
| 服务验收 | `VENDOR_SERVICE_ACCEPTED` | 对施工或服务结果作出验收结论 |
| 采购关闭 | `PROCUREMENT_CLOSED` | 订单交付、退款、押金和尾款已闭环后关闭 |

付款、退款、垫付、订金、尾款和押金一律使用资金流水，并通过关系关联采购订单，避免在采购模块重复记账。

## 5. 物料流水

| 类型 | 编码 | 来源 → 目标 | 是否改变活动总量 |
| --- | --- | --- | --- |
| 物料取得/入库 | `STOCK_IN` | 商家/外部 → 活动位置 | 增加 |
| 直接到使用点 | `STOCK_DIRECT_DELIVERY` | 商家/外部 → 使用区域 | 增加 |
| 物料领用 | `STOCK_ISSUED` | 保管位置 → 人员/任务/区域 | 不改变 |
| 物料调拨 | `STOCK_TRANSFERRED` | 活动位置 → 活动位置 | 不改变 |
| 未用物料退回 | `STOCK_RETURNED` | 人员/区域 → 保管位置 | 不改变 |
| 物料消耗 | `STOCK_CONSUMED` | 使用位置 → 已消耗 | 减少可用量 |
| 借入 | `STOCK_BORROWED_IN` | 外部所有人 → 活动位置 | 增加在手量并建立归还义务 |
| 租赁物交付 | `STOCK_RENTED_IN` | 商家 → 活动位置 | 增加在手量并建立归还义务 |
| 借出 | `STOCK_LOANED_OUT` | 活动位置 → 外部借用人 | 减少在手量，不改变所有权数量 |
| 借入/租赁物归还 | `STOCK_RETURNED_TO_OWNER` | 活动位置 → 外部所有人 | 减少在手量并结清义务 |
| 损坏 | `STOCK_DAMAGED` | 当前状态 → 损坏状态 | 依可用性减少 |
| 遗失 | `STOCK_LOST` | 当前状态 → 遗失状态 | 减少在手量 |
| 处置 | `STOCK_DISPOSED` | 活动位置 → 赠送/出售/保留/报废 | 减少活动可用量 |
| 物料盘点 | `STOCK_COUNT` | 无移动 | 不改变；记录理论量、实际量和差异 |

## 6. 任务、人员与现场流水

| 类型 | 编码 | 定义 |
| --- | --- | --- |
| 创建任务 | `TASK_CREATED` | 建立目标、责任、期限和依赖 |
| 接受任务 | `TASK_ACCEPTED` | 被指派人明确接受责任 |
| 开始任务 | `TASK_STARTED` | 任务进入实际执行 |
| 暂停任务 | `TASK_PAUSED` | 记录暂停原因和恢复条件 |
| 任务阻塞 | `TASK_BLOCKED` | 记录等待资源、他人、批准或异常 |
| 恢复任务 | `TASK_RESUMED` | 阻塞或暂停原因解除并继续执行 |
| 任务转交 | `TASK_HANDED_OVER` | 责任从原负责人转至新负责人并保留进度 |
| 资源交接 | `RESOURCE_HANDED_OVER` | 保管责任和实际资源一起转移 |
| 声明完成 | `TASK_COMPLETED` | 执行人声明工作完成 |
| 任务验收 | `TASK_VERIFIED` | 有权限的人确认结果通过或不通过 |
| 取消任务 | `TASK_CANCELLED` | 记录取消原因，不删除历史 |
| 班次交接 | `SHIFT_HANDED_OVER` | 班次责任、待办、风险和资源转交 |
| 施工变更 | `SITE_WORK_CHANGED` | 记录施工或装饰的现场变更及确认依据 |
| 区域状态更新 | `AREA_STATUS_UPDATED` | 记录区域开放、占用、风险或恢复状态 |
| 车辆出发/到达 | `VEHICLE_TRIP_UPDATED` | 记录运输任务关键节点，不包含实时定位 |

## 7. 记录治理流水

| 类型 | 编码 | 定义 |
| --- | --- | --- |
| 候选已生成 | `CANDIDATE_CREATED` | 从文字、语音、图片或导入数据生成候选结构 |
| 候选已确认 | `CANDIDATE_CONFIRMED` | 有权限的人确认候选并生成或关联正式事实 |
| 候选已拒绝 | `CANDIDATE_REJECTED` | 拒绝错误候选并保留原因 |
| 记录已更正 | `RECORD_CORRECTED` | 新记录替代原记录参与计算 |
| 记录已作废 | `RECORD_VOIDED` | 原记录停止参与有效计算 |
| 争议已提出 | `DISPUTE_OPENED` | 对金额、数量、责任或证据提出争议 |
| 争议已解决 | `DISPUTE_RESOLVED` | 保存结论、依据和后续更正 |

## 8. 场景验证

| 场景 | 必需流水与关系 |
| --- | --- |
| 一人代三个家庭合并送礼 | `GIFT_PAYMENT_RECEIVED` + 三条 `GIFT_PAYMENT_ALLOCATED` |
| 收礼人分两次转给管账人 | 一条实际收款 + 两条 `GIFT_HANDED_OVER`/内部转移 |
| 主账户转理事、换现、交采购人 | 内部转移 → 换现 → 现金交接；均不增加支出 |
| 领 3,000 元备用金，花 1,980 元，退 1,020 元 | 发放 → 两笔支出 → 余款退回，并关联同一备用金 |
| 个人垫付后分两次报销 | 一条垫付 + 两条报销，报销合计不超待偿余额 |
| 一笔报销结清三笔垫付 | 一条报销通过三条结算关系分配到三笔垫付 |
| 商家订金、增项、尾款和押金退回 | 订单 + 订金 + 采购变更 + 尾款 + 押金退回 |
| 物料直接送厨房，部分调接待区 | 直接到使用点 + 内部调拨 |
| 租赁桌椅损坏并扣押金 | 租赁交付 + 损坏 + 押金差异处理 + 真实成本确认 |
| 任务负责人离场并交出现金、钥匙 | 任务转交 + 多条资源交接 |
| 同一支付截图被两人上传 | 两个原始输入可保留，只确认一条正式资金流水并标记疑似重复 |
| 断网后同一记录重试 | 相同幂等键只生成一条正式流水 |
| 礼簿照片识别到同名人员 | 原始输入 + 多个 AI 候选，人工消歧后确认 |
| 一句话包含备用金、两笔支出和交接 | 一个原始输入拆为四条候选流水，分别确认 |
| 活动结束仍有尾款、退款和借用物 | 通过未闭环关系分别生成待付款、待退款、待归还项 |

上述场景证明类型体系能表达当前已知案例，但不代表 Issue #2 要求的 20 个真实业务故事已经完成。
