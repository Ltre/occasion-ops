# 测试记录指南

本目录保存与开发进度对应的实时测试记录。测试记录是功能完成证明的一部分，不是发布前临时补写的总结。

## 1. 文件命名

统一使用：

```text
test-YYMMDD-功能名称或描述.md
```

示例：

```text
test-260722-money-quick-entry.md
```

其对应开发进度文件应为：

```text
docs/dev-process/dev-260722-money-quick-entry.md
```

日期和功能描述应保持一致，前缀分别使用 `dev-` 与 `test-`。

## 2. 创建和更新时机

- 开始开发任务时，与开发进度文件一起创建；
- 写出测试计划和待验证验收标准；
- 每次运行测试后实时追加命令、环境和结果；
- 发现失败、缺陷或未测场景时立即记录；
- PR 或 CI 运行后补充链接和结果；
- 功能完成时给出最终结论。

## 3. 状态

- `not-started`
- `in-progress`
- `passed`
- `failed`
- `blocked`
- `partial`

## 5. 资金功能最低测试要求

涉及资金流水的功能至少覆盖：

- 正常收款、支出和内部转移；
- 来源、目标和金额校验；
- 重复点击与超时重试；
- 并发修改；
- 弱网恢复；
- 已确认记录的更正和作废；
- 权限越权；
- 流水重建余额；
- 备份恢复；
- 待确认记录不进入正式余额；
- 内部转移不重复计入收支；
- 报销不产生第二次成本。

## 6. 完成要求

只有在以下条件满足后，测试状态才可以标为 `passed`：

- 所有范围内验收标准均有测试证据；
- 自动化和人工测试结果已记录；
- 失败项已修复或拆为明确 Issue；
- 未测项有合理原因且不影响发布门槛；
- 相关 commit、PR 或 CI 可追溯；
- 对应开发进度文件同步更新。
