## 人工与场景测试

### 场景 1：开发者误提交 `.env`

期望：规范明确禁止真实值进入仓库；Secret 扫描应阻止提交；若已提交必须撤销或轮换，而不是只删除文件。

状态：待验证。

### 场景 2：单机部署

期望：Secret 位于发布目录之外，仅专用服务账号可读；目录和文件权限过宽时应用拒绝启动。

状态：待验证。

### 场景 3：多节点部署

期望：节点通过工作负载身份读取远程加密 Secret；不人工复制明文文件；本地只在内存、`tmpfs` 或只读挂载短期存在。

状态：待验证。

### 场景 4：Secret 轮换

期望：支持版本和短暂双版本窗口；所有节点完成切换后撤销旧版本；过程可审计。

状态：待验证。

### 场景 5：Secret Store 暂时不可用

期望：关键 Secret 无法安全取得时应用失败关闭；非关键增强服务可明确降级，不影响核心资金手工记录。

状态：待验证。

### 场景 6：不可信 PR

期望：CI 不向外部分支或不可信 PR 注入生产 Secret，日志和构建产物不包含秘密。

状态：待验证。

### 场景 7：区域部署

期望：中国大陆与海外环境使用区域内 Secret Store；未明确配置时不跨区域或跨境复制。

状态：待验证。

## 权限、安全与审计测试

文档必须明确：

- 服务只能读取自身需要的最小 Secret；
- 普通应用不能读取根密钥；
- Secret 的读取、更新、撤销和轮换可审计；
- Secret 值不会进入审计日志；
- 高敏根密钥由 KMS、HSM 或同等级服务保护；
- 前端、小程序和移动端包不包含服务端 Secret。

状态：待验证。

## 幂等、并发与恢复测试

文档必须明确：

- 多节点轮换不会造成不可恢复的不一致；
- Secret 更新支持版本和受控切换；
- 旧版本撤销前确认所有节点已切换；
- 远程备份必须加密；
- 恢复不会产生明文 Secret 副本；
- Secret Store 故障边界和缓存期限明确。

状态：待验证。
