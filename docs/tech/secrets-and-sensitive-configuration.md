# 密钥与敏感配置管理策略

> 状态：当前技术基线  
> 适用阶段：本地开发、CI/CD、单机部署及多节点生产环境  
> 更新日期：2026-07-22

## 1. 结论

OccasionOps 的任何密钥、Token、密码、证书私钥和其他保密配置都不得保存到代码仓库中。

仓库只允许保存：

- 配置字段定义；
- 非敏感默认值；
- Secret 引用名或引用 ID；
- 不含真实值的示例文件；
- 密钥读取接口、权限规则和部署说明。

真实秘密至少保存在仓库外、仅服务账号可读的受限目录中。多节点、远程部署或较高安全等级的环境，应采用以下分层结构：

```text
代码与普通配置
    │ 只保存 Secret 引用，不保存真实值
    ▼
远程加密秘密存储
    │ KMS／主密钥保护、版本、审计、轮换
    ▼
工作负载身份或短期引导凭证
    │ 按服务和环境授予最小读取权限
    ▼
节点本地受限目录、内存或 tmpfs
    │ 只读、短生命周期、禁止进入镜像和备份
    ▼
应用进程
    └── 按需读取，日志和错误中不输出秘密
```

## 2. 适用范围

本策略适用于但不限于：

- 第三方 API Key；
- OAuth Client Secret；
- Access Token、Refresh Token 和长期会话签名密钥；
- 数据库、Redis、消息队列和对象存储访问凭证；
- 阿里云、腾讯云及国际云厂商的访问密钥；
- Webhook 签名密钥；
- JWT、Cookie 和临时链接签名密钥；
- TLS 私钥和客户端证书私钥；
- 服务账号 JSON、私钥文件和机器凭证；
- 数据加密主密钥、备份加密密钥和迁移密钥；
- 短信、邮件、微信平台和支付渠道密钥；
- AI、OCR 和其他模型服务访问凭证；
- 任何一旦泄露可读取、修改、删除数据或产生费用的配置。

普通公开配置，例如公开 API 地址、功能开关名称、分页大小和非敏感区域代码，可以进入仓库，但必须与秘密值分离。

## 3. 仓库零秘密规则

### 3.1 禁止进入仓库的内容

以下位置均不得包含真实秘密：

- 源代码；
- `.env`、YAML、JSON、TOML 或其他配置文件；
- Git 历史；
- 测试夹具、快照和示例数据；
- Markdown 文档；
- Issue、PR 描述和评论；
- CI 日志、构建日志和测试输出；
- 截图、录屏和附件；
- 容器镜像、前端构建产物和移动端安装包；
- 数据库迁移文件和种子脚本。

`.gitignore` 只能作为最后一道防误提交措施，不能被视为秘密管理方案。

### 3.2 允许提交的示例配置

可以提交：

```text
.env.example
config.example.yaml
secrets.schema.json
```

但其中只能包含占位符，例如：

```text
DATABASE_PASSWORD_FILE=/run/occasionops/secrets/database-password
OBJECT_STORAGE_ACCESS_KEY_REF=prod/object-storage/access-key
JWT_SIGNING_KEY_REF=prod/auth/jwt-signing-key
```

不得放入看似测试、实为仍然有效的真实凭证。

### 3.3 泄露处理

秘密一旦被提交，即使随后删除文件，也必须视为已经泄露。必须立即：

1. 撤销或轮换相关秘密；
2. 检查访问日志和异常使用；
3. 使相关会话或令牌失效；
4. 评估是否需要清理 Git 历史；
5. 建立安全事件记录和修复 Issue；
6. 补充扫描或流程门禁，避免再次发生。

## 4. 配置与秘密分离

应用配置分为三类：

### 4.1 普通配置

可进入仓库或普通配置中心，例如：

- 服务端口；
- 区域代码；
- 功能开关；
- 非敏感超时和重试次数；
- Secret 引用名。

### 4.2 敏感配置

不能进入仓库，例如：

- 用户名和密码组合；
- 带访问权限的连接字符串；
- API Token；
- 私钥。

敏感配置应使用 Secret 引用：

```ts
interface SecretReference {
  provider: string;
  path: string;
  version?: string;
}
```

业务配置只保存 `SecretReference`，不保存解析后的值。

### 4.3 高敏根密钥

用于加密其他秘密、备份或数据的根密钥不得直接提供给普通应用代码。应由 KMS、HSM 或等价密钥服务持有，应用仅请求执行解密、签名或数据密钥生成操作。

## 5. 本地开发最低要求

优先使用操作系统密钥链、开发环境 Secret Store 或受控开发工具保存秘密。

如果必须使用文件，至少满足：

- 文件位于仓库目录之外；
- 父目录仅当前用户可进入，建议权限为 `0700`；
- Secret 文件仅当前用户可读写，建议权限为 `0600`；
- 不放入网盘、公开同步目录或未加密备份；
- 不使用生产凭证；
- 使用最小权限、短有效期的开发凭证；
- 启动时检查权限过宽并拒绝继续运行；
- 调试输出不得打印秘密值。

示例目录仅表达结构，不作为固定部署路径：

```text
<outside-repository>/occasionops-secrets/
├── database-password
├── object-storage-access-key
└── external-api-token
```

## 6. 单机服务端部署

单机生产或测试环境至少采用受限目录或只读 Secret 挂载：

- Secret 目录位于应用代码和发布目录之外；
- 由专用服务账号拥有；
- 目录建议 `0700`，文件建议 `0400` 或 `0600`；
- 应用进程只获得自身所需文件的读取权限；
- 不允许 API、Worker、备份进程共用一个全权限 Secret 包；
- 容器环境使用只读 Secret Mount，不写入镜像层；
- 可行时使用内存文件系统或 `tmpfs`；
- 普通系统备份不得无差别复制明文 Secret 目录；
- Secret 变更后支持安全重载或受控重启；
- 删除或替换旧版本时保留操作审计，但不记录秘密内容。

环境变量容易出现在进程诊断、崩溃信息、调试工具和错误日志中，因此不作为长期秘密的首选承载方式。不可避免使用时，只应用于短期引导凭证，并必须限制进程和日志暴露。

## 7. 多节点与远程部署

多节点环境不得依靠人工把同一份明文文件复制到各服务器。

应采用远程加密 Secret Store，并具备：

- 静态加密；
- TLS 传输加密；
- KMS 或等价主密钥保护；
- 按环境、区域、服务和用途隔离命名空间；
- 最小权限访问策略；
- Secret 版本；
- 创建、读取、更新、撤销和轮换审计；
- 过期时间和自动轮换能力；
- 访问异常告警；
- 可恢复的备份，但备份本身必须加密。

可采用云厂商托管的密钥／秘密管理服务、Vault 类系统或满足同等能力的内部服务。业务代码只依赖项目定义的 Secret Provider 接口。

建议接口：

```ts
interface SecretProvider {
  getSecret(ref: SecretReference): Promise<SecretValue>;
  getSecretMetadata(ref: SecretReference): Promise<SecretMetadata>;
  invalidate?(ref: SecretReference): Promise<void>;
}
```

可用实现包括：

```text
LocalFileSecretProvider
CloudManagedSecretProvider
VaultCompatibleSecretProvider
TestSecretProvider
```

应用模块不得直接依赖某一家云厂商 SDK。

## 8. 分层交付模型

### 8.1 控制层

保存 Secret 元数据、版本、权限、轮换策略和审计。真实值以远程加密形式保存。

### 8.2 身份层

节点或工作负载通过机器身份、实例角色、工作负载身份或短期证书访问 Secret Store。优先避免长期静态 Access Key。

### 8.3 节点层

节点只获取本服务当前需要的 Secret。可以：

- 直接保存在进程内存；
- 写入仅服务账号可读的 `tmpfs`；
- 通过只读 Secret Volume 暴露。

不得长期写入普通磁盘、应用目录或共享目录。

### 8.4 应用层

应用只读取解析后的 Secret，不负责保存、同步或复制秘密。日志、指标、追踪、异常和健康检查必须对秘密进行屏蔽。

## 9. 最小权限

每个 Secret 必须同时限制：

- 哪个环境可访问；
- 哪个服务可访问；
- 哪个区域可访问；
- 可读取、更新还是轮换；
- 可调用的第三方 API 范围；
- 可访问的 Bucket、数据库、队列或模型；
- 有效期和来源网络。

示例：附件 Worker 的对象存储凭证不应同时拥有用户管理或数据库管理员权限；只上传附件的客户端临时凭证不能列出整个 Bucket 或删除其他对象。

## 10. 区域与跨境要求

Secret 应与对应部署区域和数据驻留策略一致：

- 中国大陆环境优先使用区域内 Secret Store 和 KMS；
- 海外环境使用就近区域的 Secret Store；
- 不默认跨境复制 Secret；
- 不同区域可以使用相同逻辑引用名，但实际值可以不同；
- 跨区域同步必须经过明确评审、加密、审计和最小权限控制；
- 根密钥和生产高敏 Secret 应尽量保持区域隔离。

## 11. CI/CD

CI/CD 必须遵守：

- 构建和测试不依赖写入仓库的真实 Secret；
- CI 使用平台 Secret Store 或工作负载身份；
- 云资源访问优先使用短期身份交换，而不是长期 Access Key；
- 来自外部分支或不可信 PR 的任务默认不注入生产 Secret；
- 日志自动屏蔽已知 Secret；
- 命令不得把 Secret 写入终端输出、构建参数或缓存键；
- 构建产物不得包含 `.env`、私钥或运行 Secret；
- 部署阶段只传递 Secret 引用，目标环境自行解析；
- Secret 扫描应覆盖提交、PR 和构建产物。

## 12. 轮换与生命周期

每个生产 Secret 至少记录：

- 所有者；
- 用途；
- 权限范围；
- 创建时间；
- 当前版本；
- 过期或轮换时间；
- 依赖服务；
- 撤销步骤；
- 泄露后的影响范围。

轮换设计应支持短暂双版本窗口，避免多节点发布过程中出现一半新密钥、一半旧密钥的不可恢复状态。旧版本应在确认所有节点切换后撤销。

长期不使用的 Secret 必须禁用或删除，不能只留在列表中。

## 13. 日志、错误与可观测性

禁止记录：

- Secret 原值；
- 完整 Authorization Header；
- Cookie、Refresh Token 和签名参数；
- 含密码的数据库连接字符串；
- 私钥正文；
- 云厂商访问密钥；
- Secret 文件内容。

可以记录：

- Secret 引用 ID；
- 版本号；
- Provider；
- 加载成功或失败；
- 轮换时间；
- 被拒绝的访问主体；
- 不含秘密值的错误分类。

屏蔽规则本身不能依赖“开发者记得不打印”，应在日志框架、HTTP 拦截器和错误序列化层统一实现。

## 14. 启动与失败策略

关键 Secret 缺失、权限过宽、格式无效或无法解密时，应用应失败关闭，不得：

- 使用写死的后备生产密钥；
- 自动降级为匿名或无鉴权模式；
- 把 Secret 输出到日志帮助调试；
- 继续运行并生成不可验证的数据。

非关键第三方服务 Secret 缺失时，可以禁用对应功能，但必须明确显示降级状态，且不能影响核心资金手工记录。

## 15. 测试要求

实现阶段至少覆盖：

- 仓库和 Git 历史 Secret 扫描；
- `.env.example` 只包含占位符；
- 构建产物不包含 Secret；
- Secret 目录权限过宽时启动失败；
- 非授权服务无法读取 Secret；
- 多服务只能读取各自最小集合；
- Secret 缺失、过期和撤销；
- 轮换期间新旧版本兼容；
- 多节点逐步轮换；
- Secret Store 暂时不可用时的缓存与失败边界；
- 日志、错误、追踪和健康检查不泄露 Secret；
- CI 对不可信 PR 不注入生产 Secret；
- 备份和恢复不会产生明文 Secret 副本；
- 区域部署不会未经配置跨境同步 Secret。

测试记录必须保存到对应 `docs/test-log/test-*.md` 中，但测试证据本身不得包含真实 Secret。

## 16. P0 开发要求

首期必须完成：

- 定义 Secret 引用和 `SecretProvider` 接口；
- 增加仓库忽略规则和示例配置；
- 建立提交与 CI Secret 扫描；
- 建立本地受限目录 Provider；
- 对目录和文件权限进行启动校验；
- 建立统一日志脱敏；
- 禁止 Secret 进入前端、小程序包和容器镜像；
- 为数据库、Redis、对象存储、微信平台和外部 API 使用独立 Secret；
- 记录 Secret 元数据和轮换责任，但不记录 Secret 值。

## 17. P1 与后续要求

生产多节点前必须完成：

- 接入远程加密 Secret Store；
- 使用工作负载身份或短期引导凭证；
- 建立 Secret 版本和轮换流程；
- 建立访问审计和异常告警；
- 建立节点内存或只读临时挂载；
- 验证远程服务不可用时的启动和运行边界；
- 完成备份恢复和灾难恢复演练；
- 对高敏根密钥采用 KMS、HSM 或同等级保护。

## 18. 验收标准

- 仓库及其构建产物中不存在真实 Secret；
- 普通配置与秘密值完全分离；
- 单机环境至少使用仓库外受限目录；
- 多节点环境使用远程加密 Secret Store；
- 应用只获得本服务所需的最小 Secret 集合；
- Secret 访问、版本和轮换可以审计；
- 日志、错误和监控不会泄露秘密；
- Secret 缺失或权限错误时系统安全失败；
- Secret 可以轮换且不会造成不可恢复的多节点不一致；
- 未经明确配置不会跨区域或跨境复制 Secret；
- 泄露事件有撤销、轮换、审计和修复流程。
