# 对象存储与区域部署策略

> 状态：当前技术方向  
> 适用阶段：MVP 至早期生产阶段  
> 更新日期：2026-07-22

## 1. 结论

OccasionOps 主要面向中国大陆用户，首期生产环境的对象存储应优先选择中国大陆访问质量、网络路径和运维支持更合适的国内云厂商。

首期候选包括：

- 阿里云 OSS；
- 腾讯云 COS；
- 后续按需要评估华为云 OBS 或其他国内对象存储。

系统同时保留海外部署和国际对象存储适配能力，例如：

- AWS S3；
- Cloudflare R2；
- 其他具备稳定对象存储 API 的区域服务。

系统不能把业务代码绑定到某一家厂商，也不能假设所有对象存储都完整兼容 AWS S3 API。应定义项目自己的对象存储接口，并为不同厂商实现适配器。

## 2. 基本原则

1. **国内用户优先**：中国大陆生产环境默认选择国内区域和国内云对象存储；
2. **海外可选**：海外用户或海外部署可选择就近国际存储；
3. **数据驻留明确**：一个活动、组织或部署环境的数据存储区域必须可识别、可审计；
4. **不默认跨境复制**：附件不得在未明确配置和评审的情况下自动跨境复制；
5. **厂商可替换**：业务模块只依赖统一存储接口；
6. **私有访问**：附件默认私有，服务端鉴权后签发短期访问凭证；
7. **元数据归数据库**：PostgreSQL 保存对象元数据、归属、关联和审计，对象存储只保存文件本体；
8. **迁移可验证**：更换厂商或区域时必须校验文件完整性、引用和访问权限。

## 3. 为什么不直接把 S3 作为唯一实现

“S3 兼容”可以作为一种适配能力，但不应成为业务层唯一假设：

- 国内厂商在签名、回调、生命周期、分片上传、事件通知和访问域名上可能存在差异；
- 某些厂商提供兼容接口，但并非所有能力和边界行为都与 AWS S3 一致；
- 中国大陆访问海外存储可能出现延迟、抖动、失败率和跨境链路问题；
- 海外用户访问中国大陆存储也可能体验不佳；
- 厂商 SDK、临时凭证和 CDN 集成方式不同。

因此，S3 是一个 `StorageProvider` 实现，不是整个系统的领域模型。

## 4. 存储提供者抽象

建议定义统一接口：

```ts
interface ObjectStorageProvider {
  createUploadSession(input: CreateUploadSessionInput): Promise<UploadSession>;
  completeUpload(input: CompleteUploadInput): Promise<StoredObject>;
  createDownloadUrl(input: DownloadUrlInput): Promise<SignedUrl>;
  headObject(input: ObjectRef): Promise<ObjectMetadata>;
  copyObject(input: CopyObjectInput): Promise<StoredObject>;
  deleteObject(input: DeleteObjectInput): Promise<void>;
  listParts?(input: MultipartUploadRef): Promise<UploadedPart[]>;
  abortUpload?(input: MultipartUploadRef): Promise<void>;
}
```

适配器可以包括：

```text
AliyunOssStorageProvider
TencentCosStorageProvider
AwsS3StorageProvider
CloudflareR2StorageProvider
LocalDevelopmentStorageProvider
```

业务模块不得直接引用厂商 SDK。厂商 SDK 只存在于基础设施适配层。

## 5. 存储配置模型

建议按“部署环境或组织存储策略”配置，而不是让普通用户逐文件选择厂商。

配置至少包含：

- `provider`：OSS、COS、S3、R2 等；
- `region`：实际数据区域；
- `bucket`；
- `endpoint`；
- `public_endpoint` 或 CDN 域名；
- `credential_reference`：密钥引用，不保存明文密钥；
- `data_residency`：中国大陆、香港、海外区域等逻辑标识；
- `encryption_mode`；
- `lifecycle_policy`；
- `status`：active、read-only、migrating、disabled；
- `is_default`。

每个附件元数据至少记录：

- 存储配置 ID；
- 对象键；
- 原始文件名；
- MIME 类型和大小；
- 内容哈希；
- 所属活动和上传人；
- 关联业务对象；
- 上传、处理、删除和迁移状态；
- 创建时间、确认时间和审计信息。

不能只保存一个完整公网 URL。URL 可能因域名、CDN、迁移或签名失效而变化。

## 6. 国内与海外部署模式

### 6.1 中国大陆部署

默认建议：

- API、数据库、Redis、Worker 和对象存储尽量部署在同一云或相近区域；
- 对象存储优先阿里云 OSS 或腾讯云 COS；
- 附件处理 Worker 使用内网或同区域链路读取；
- 下载通过服务端鉴权后签发短期地址；
- 是否使用 CDN 按真实访问量和文件类型评估；
- 域名、备案、数据保护和安全合规在上线前单独评审。

### 6.2 海外部署

海外部署可以选择：

- AWS S3；
- Cloudflare R2；
- 海外区域的阿里云 OSS 或腾讯云 COS；
- 其他经过适配和验证的对象存储。

选择标准包括：

- 用户主要所在地；
- API、数据库和 Worker 所在区域；
- 上传和下载延迟；
- 数据驻留要求；
- 成本和流量计费；
- 备份恢复能力；
- SDK 与运维成熟度。

### 6.3 多区域原则

初期不做自动多主或所有附件全球复制。

建议：

- 一个部署环境有一个主数据区域；
- 一个对象默认有一个权威存储位置；
- 跨区域复制必须是明确策略；
- 复制对象需要记录源、目标、状态和校验结果；
- 删除、保留和法律要求必须能传播到复制副本；
- 海外扩展优先独立区域部署，而不是让所有客户端跨洲访问同一存储桶。

## 7. 上传流程

推荐流程：

```text
客户端请求上传
→ 服务端校验活动、角色、文件类型和大小
→ 服务端生成上传会话与对象键
→ 客户端直传对象存储或通过受控上传服务
→ 客户端通知完成
→ 服务端校验对象元数据、大小和哈希
→ PostgreSQL 将附件标记为已上传
→ Worker 执行压缩、缩略图、OCR 或病毒扫描
→ 处理结果写回数据库
```

关键要求：

- 未经服务端授权不能任意选择对象键；
- 上传凭证短时有效、权限最小；
- 完成回调必须幂等；
- 不能只相信客户端报告的文件大小和 MIME 类型；
- 正式业务记录应关联已确认的附件元数据，而不是临时上传地址；
- 上传失败和弱网重试不能创建多个无法识别的附件。

## 8. 下载和预览

- 存储桶默认私有；
- 服务端先校验活动成员身份和数据范围；
- 使用短期签名 URL 或受控代理下载；
- 高敏感附件可限制有效期、下载次数或只允许预览；
- 日志记录访问人、活动、附件和时间；
- CDN 不能绕过服务端授权；
- 缩略图和派生文件继承原文件权限。

## 9. 安全要求

- 访问密钥存入密钥管理或部署环境秘密，不写入仓库或数据库明文字段；
- 生产环境优先使用角色、临时凭证或最小权限子账号；
- 存储桶禁止匿名写入；
- 默认禁止公开读；
- 对象键不得包含身份证号、手机号、真实姓名等敏感信息；
- 开启服务端加密或厂商等价能力；
- 上传文件需要类型、大小、扩展名和内容检查；
- 对可执行文件和高风险格式进行阻止或隔离；
- 删除采用业务状态、保留期和对象删除组合流程；
- 关键操作写入审计。

## 10. 备份与恢复

对象存储不是数据库备份的替代品，数据库备份也不能证明附件可恢复。

应分别验证：

- PostgreSQL 备份中附件元数据完整；
- 存储桶版本控制或备份策略符合恢复目标；
- 从数据库记录能够定位对象；
- 从对象清单能够发现孤儿文件；
- 恢复后哈希、大小、权限和业务关联一致；
- 被删除或迁移中的对象状态可解释；
- OCR、缩略图等派生文件可重建或恢复。

## 11. 厂商迁移

迁移必须是可恢复、可暂停的后台任务：

```text
创建目标存储配置
→ 目标配置进入 migrating
→ 分批复制对象
→ 校验大小与内容哈希
→ 更新附件存储引用
→ 保留源对象观察期
→ 切换为 active
→ 处理源对象保留或删除
```

迁移要求：

- 不直接覆盖原对象引用；
- 每个对象记录迁移状态和错误；
- 重试幂等；
- 迁移期间读取可回退到源存储；
- 写入目标必须明确；
- 切换前抽样和全量统计校验；
- 删除源数据需要单独审批和审计。

## 12. 首期实现范围

首期至少实现：

1. 项目级 `ObjectStorageProvider` 接口；
2. 一个国内生产适配器：阿里云 OSS 或腾讯云 COS；
3. 一个本地开发适配器；
4. 一个国际适配器的接口验证，建议 AWS S3 或 Cloudflare R2；
5. 私有桶、短期上传和下载授权；
6. 对象元数据、哈希和附件状态；
7. 幂等上传完成；
8. 图片和票据的基本压缩或缩略图任务；
9. 备份恢复与孤儿对象检查方案；
10. 存储配置可替换，不在业务代码中散落厂商判断。

首期不要求同时购买或运行多个生产厂商。可以先选一个国内主提供者，但适配边界必须从第一版存在。

## 13. 测试要求

至少覆盖：

- 国内适配器上传、下载、删除和元数据读取；
- 国际适配器契约测试；
- 文件大小、类型和权限校验；
- 短期凭证过期；
- 重复完成回调；
- 弱网和分片上传恢复；
- 跨用户和跨活动越权；
- 对象不存在或被删除；
- Worker 处理失败重试；
- 数据库恢复后附件定位；
- 哈希校验和迁移重试；
- 不同适配器通过同一套契约测试。

## 14. 非目标

初期不实现：

- 全球自动多主对象存储；
- 默认跨境复制；
- 让普通用户逐附件选择云厂商；
- 将对象存储作为正式资金或业务数据源；
- 永久公开附件 URL；
- 依赖单一厂商专有能力而不做隔离；
- 为尚未出现的流量提前建设复杂 CDN 和多区域同步。

## 15. 验收标准

- 中国大陆生产环境有明确国内对象存储方案；
- 海外部署保留国际对象存储选择；
- 业务代码不直接依赖单一厂商 SDK；
- 附件元数据和存储位置可审计；
- 私有访问、短期授权和最小权限生效；
- 不发生未明确配置的跨境复制；
- 备份恢复和厂商迁移有可执行方案；
- 国内与国际适配器能够通过统一契约测试。
