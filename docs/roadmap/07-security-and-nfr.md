# 权限、安全、审计与非功能要求

## 1. 目标

OccasionOps 涉及礼金、账户、现金、人员关系、联系方式、供应商、附件和责任记录。系统必须从第一版开始具备最小权限、可审计、可恢复、弱网可靠性和 Secret 安全管理，不能等功能完成后再补安全。

本文件表达当前有效的产品与工程安全要求。密钥和敏感配置的具体技术基线见：

- `docs/tech/secrets-and-sensitive-configuration.md`

## 2. 权限模型

采用“角色权限＋数据范围＋记录关系”的组合，而不是只做固定角色菜单。

### 2.1 角色权限（RBAC）

定义某类角色可以执行哪些动作，例如：

- 创建资金流水；
- 确认礼金归属；
- 查看活动总余额；
- 审批或确认采购；
- 盘点物料；
- 分派任务；
- 管理成员和临时入口；
- 查看审计记录。

### 2.2 数据范围（ABAC）

在角色基础上继续判断：

- 是否属于同一活动；
- 是否为本人提交；
- 是否为本人负责的任务；
- 是否属于本人管理的资金位置或区域；
- 数据是否被标记为敏感；
- 临时授权是否仍有效；
- 活动是否已归档。

### 2.3 建议数据分级

- **普通**：公开任务、场地安排、一般物料；
- **内部**：采购价格、商家联系、成员联系方式；
- **敏感**：礼金明细、资金余额、垫付和报销；
- **高度敏感**：银行账户、身份证明、争议、责任记录、Secret 元数据和安全事件。

## 3. 角色示例

### 活动总负责人

可查看全局摘要和重大异常，但高风险操作仍应保留二次确认。

### 管账人员

可管理资金、礼金、垫付、报销和盘点，不默认拥有成员管理或系统配置权限。

### 收礼人员

可创建和修改本人负责时段的收款记录；是否可看总礼金由活动策略决定。

### 采购人员

可提交需求、订单、付款和到货，默认只能查看与自己相关或公开的采购事项。

### 临时提交者

只能通过指定入口提交有限类型记录，通常只能查看本人提交结果。

### 商家

只能查看与自身有关的订单、到场、验收和结算状态。

### 审核人员

可查看流水、附件和修改历史，但不能直接付款或删除事实。

### 系统运维人员

只获得运行、监控和部署所必需的权限，不因运维职责自动获得完整业务数据或全部 Secret。业务数据访问和 Secret 管理权限应尽量分离。

## 4. 高风险操作

以下操作应支持二次确认、额外权限或双人复核：

- 大额支出；
- 修改已确认金额；
- 作废资金流水；
- 礼金重新归属；
- 关闭盘点差异；
- 手工调整资金或库存余额；
- 导出完整礼金和财务数据；
- 创建长期有效的外部访问；
- 归档或删除活动；
- 批量修改记录；
- 创建、导出或提升长期访问凭证；
- 修改生产 Secret 权限、轮换策略或跨区域复制规则；
- 使用应急访问权限读取高敏配置。

金额阈值应由活动配置，而不是写死。

## 5. 审计要求

所有关键业务操作应记录：

- 操作人；
- 操作时间；
- 客户端和会话信息；
- 原值和新值；
- 操作原因；
- 关联流水；
- 是否由 AI 建议；
- 是否经过复核；
- 导入来源或外部交易标识。

所有 Secret 管理操作应记录：

- Secret 引用 ID，而不是 Secret 值；
- Provider、区域和版本；
- 访问主体和服务身份；
- 创建、读取、更新、轮换、撤销和失败事件；
- 权限变更和应急访问；
- 不含真实秘密的错误分类。

审计记录不应被普通管理员直接删除，任何日志和审计记录都不得包含 Secret 原值。

## 6. 身份与临时访问

### 正式用户

- 支持手机号、邮箱或第三方登录；
- 敏感角色建议启用多因素认证；
- 会话可撤销；
- 设备丢失后可强制退出。

### 临时用户

- 一次性链接或二维码包含短期令牌；
- 令牌只允许指定活动和指定动作；
- 设置过期时间、最大使用次数和撤销能力；
- 不在链接中暴露敏感业务数据；
- 访问和提交均记录审计日志。

### 服务身份

- API、Worker、备份、迁移和部署任务使用独立服务身份；
- 不共享一个全权限账号；
- 多节点优先使用工作负载身份、实例角色或短期证书；
- 避免长期静态 Access Key；
- 每个服务只能读取自身所需的最小 Secret 集合。

## 7. 数据保护

- 全程使用传输加密；
- 敏感字段在存储层加密或脱敏；
- 附件使用私有存储和短期签名地址；
- 银行卡和身份证等信息遵循最小收集；
- 日志禁止记录完整敏感字段；
- 导出文件设置有效期和访问控制；
- 活动归档后可限制查看和编辑；
- 明确数据保留、删除和备份恢复策略；
- 前端、PWA、微信小程序和移动端安装包不得包含服务端 Secret；
- 数据备份和 Secret 备份必须分开管理并分别加密。

## 8. 密钥与敏感配置管理

### 8.1 仓库零秘密

任何 API Key、Token、密码、私钥、证书私钥、数据库凭证、对象存储凭证、微信平台密钥、AI/OCR 凭证和其他保密配置都不得保存到：

- 源代码和普通配置文件；
- Git 历史；
- 文档、Issue 和 PR；
- 测试夹具、快照和示例数据；
- 日志、截图和构建产物；
- 容器镜像、PWA、小程序或移动端安装包。

仓库只允许保存：

- 配置字段定义；
- 非敏感默认值；
- 占位符；
- Secret 引用名或引用 ID；
- 不含真实值的 `.env.example` 或示例配置。

`.gitignore` 只能防止误提交，不能代替 Secret 管理。Secret 一旦进入 Git 历史，必须立即撤销或轮换，不能只删除文件。

### 8.2 单机最低要求

单机开发、测试或生产环境至少使用仓库外的受限目录或只读 Secret 挂载：

- Secret 位于代码和发布目录之外；
- 使用专用服务账号；
- 目录建议权限为 `0700`；
- 文件建议权限为 `0400` 或 `0600`；
- 可行时使用 `tmpfs` 或内存挂载；
- 不写入容器镜像、普通备份和日志；
- 权限过宽、文件缺失或格式无效时拒绝启动。

环境变量不作为长期生产 Secret 的首选承载方式。不可避免使用时，只应用于短期引导凭证，并限制进程诊断和日志暴露。

### 8.3 多节点与远程服务

多节点部署不得依靠人工复制明文 Secret 文件。必须采用远程加密 Secret Store，并具备：

- 静态和传输加密；
- KMS、HSM 或同等级主密钥保护；
- 按环境、区域和服务隔离；
- 最小权限；
- 版本、轮换、撤销和过期；
- 访问审计和异常告警；
- 加密备份和恢复；
- 工作负载身份或短期引导凭证。

节点只获取本服务当前需要的 Secret，并仅在进程内存、`tmpfs` 或只读受限目录短期落地。

业务代码依赖项目定义的 `SecretProvider` 接口，不直接绑定某一家云厂商 SDK。

### 8.4 区域与跨境

- 中国大陆环境优先使用区域内 Secret Store 和 KMS；
- 海外环境使用就近区域服务；
- 相同逻辑引用名可以对应不同区域的不同实际值；
- 不默认跨区域或跨境复制 Secret；
- 跨区域同步必须经过明确评审、加密、审计和最小权限控制；
- 高敏根密钥应尽量保持区域隔离。

### 8.5 CI/CD

- CI 使用平台 Secret Store 或短期工作负载身份；
- 外部分支和不可信 PR 默认不注入生产 Secret；
- 构建、测试和部署日志必须屏蔽 Secret；
- 构建产物不得包含 `.env`、私钥或运行 Secret；
- 部署只传递 Secret 引用，目标环境自行解析；
- Secret 扫描覆盖提交、PR、Git 历史和构建产物。

### 8.6 轮换与泄露处置

每个生产 Secret 至少记录所有者、用途、权限范围、版本、过期时间、依赖服务、撤销步骤和泄露影响。

轮换应支持短暂双版本窗口。确认所有节点切换后，再撤销旧版本。

发现泄露时必须：

1. 立即撤销或轮换；
2. 检查访问日志和异常使用；
3. 使相关会话或令牌失效；
4. 评估并清理 Git 历史、镜像和缓存；
5. 建立安全事件与修复 Issue；
6. 增加扫描和流程门禁。

### 8.7 失败策略

关键 Secret 缺失、权限错误、过期或无法解密时，应用必须安全失败，不得使用写死后备密钥或自动关闭鉴权。

非关键第三方服务 Secret 缺失时，可以禁用对应增强功能，但必须明确显示降级状态，并且不能影响核心资金手工记录。

## 9. 一致性与可靠性

### 幂等

- 每次客户端提交携带幂等键；
- 支付截图或外部交易号用于重复检测；
- 弱网重试不应生成重复流水；
- Secret 更新和上传完成回调也必须考虑重复执行。

### 并发

- 采用版本号或条件更新；
- 多人同时修改时不静默覆盖；
- 冲突内容进入人工合并；
- 多节点 Secret 轮换必须避免一半节点永久停留在旧版本。

### 事务

以下操作需要原子性：

- 内部资金转移两端余额变化；
- 物料调拨两端数量变化；
- 报销与待报销余额结清；
- 作废与对应投影回滚；
- 盘点调整与差异记录。

## 10. 性能目标

首期建议目标：

- 高频提交接口在正常网络下快速返回；
- 首页和待办页面优先加载关键数据；
- 图片、语音上传与业务提交解耦；
- 大型活动的流水列表必须分页；
- 聚合报表异步生成；
- 现场端在低性能手机上保持可操作；
- 单个活动至少支持数百成员、数万条流水和大量附件的扩展空间；
- Secret 加载和轮换不得把正常请求长期阻塞在外部秘密服务上。

具体数值应通过试点基线测试确定。

## 11. 可用性与恢复

- 核心业务服务应有健康检查；
- 数据库定期备份；
- 附件存储具备冗余或版本保护；
- 定期演练恢复；
- 失败任务可重试并进入死信队列；
- AI 和 OCR 故障不影响基础手工记录；
- 支持活动数据导出，避免平台锁定；
- Secret Store 故障边界、短期缓存期限和安全失败条件必须明确；
- Secret 备份必须加密，恢复不能生成无人管理的明文副本；
- 恢复后应验证 Secret 版本、权限和依赖服务状态。

## 12. 可观测性

应监控：

- 登录和权限拒绝；
- 提交失败和重复请求；
- 弱网同步失败；
- 资金和库存投影不一致；
- AI 处理成功率和耗时；
- 待整理积压；
- 附件上传失败；
- 后台任务和通知失败；
- 高风险操作和异常导出；
- Secret 加载失败、权限拒绝、过期、轮换和异常读取；
- 不可信来源尝试获取 Secret；
- 日志脱敏规则失效。

日志、指标和追踪信息应使用关联 ID 串联同一次业务操作，但不得输出 Authorization Header、Cookie、Token、密码、私钥和带凭证连接字符串。

## 13. 测试策略

### 单元测试

重点覆盖金额、余额、数量、状态机、权限、重复检测、Secret 引用解析和脱敏规则。

### 集成测试

覆盖内部转移、垫付报销、采购到货、库存调拨、任务交接、Secret Provider 权限与轮换。

### 场景测试

使用真实业务故事测试多人、多账户、弱网、先记录后整理、冲突合并、Secret 缺失和外部服务降级。

### 安全测试

- 越权访问；
- 临时链接泄露；
- 附件权限；
- 敏感信息日志；
- 批量导出；
- 重放和重复提交；
- 仓库及 Git 历史 Secret 扫描；
- 构建产物 Secret 扫描；
- 受限目录权限；
- 未授权服务读取 Secret；
- 不可信 PR 注入保护；
- 日志、错误、追踪和健康检查脱敏；
- Secret 撤销、过期和轮换；
- 未配置时不跨区域复制 Secret。

### 恢复测试

验证数据库恢复、附件恢复、投影重建、离线队列重放、Secret Store 恢复和多节点轮换恢复。

## 14. 开发计划

### P0

- 完成权限矩阵和数据分级；
- 确定审计事件格式；
- 确定幂等、版本和事务原则；
- 设计数据保留和附件访问策略；
- 建立基础威胁模型；
- 定义 `SecretReference` 和 `SecretProvider`；
- 建立仓库、提交和 CI Secret 扫描；
- 建立不含真实值的示例配置；
- 建立仓库外本地受限目录 Provider；
- 启动时校验目录和文件权限；
- 建立统一日志与错误脱敏；
- 禁止 Secret 进入前端、小程序、镜像和构建产物；
- 为数据库、Redis、对象存储、微信平台和外部 API 使用独立 Secret。

### P1

- 活动级角色权限；
- 数据范围校验；
- 审计日志；
- 幂等提交；
- 条件更新和冲突响应；
- 私有附件访问；
- 基础备份和健康检查；
- 接入远程加密 Secret Store；
- 使用工作负载身份或短期引导凭证；
- 建立 Secret 版本、轮换和撤销；
- 建立 Secret 访问审计和异常告警；
- 建立节点内存、`tmpfs` 或只读挂载；
- 验证远程 Secret Store 故障和多节点轮换。

### P2

- 临时链接和撤销；
- 高风险操作复核；
- 数据导出和归档；
- 弱网同步监控；
- 安全告警；
- 投影一致性检查和重建；
- Secret 自动轮换；
- 区域隔离和跨区域审批；
- 应急访问与双人复核；
- Secret 备份恢复演练。

### P3

- 多因素认证；
- 更细粒度敏感字段策略；
- 自动化恢复演练；
- 审计分析；
- 组织级治理和合规配置；
- 高敏根密钥的 HSM 或同等级保护；
- 多区域 Secret 治理与持续合规检查。

## 15. 验收标准

- 临时用户无法读取未授权数据；
- 不同角色的数据可见范围通过自动化测试；
- 弱网重复提交不会生成重复流水；
- 内部转移和物料调拨具备原子性；
- 已确认记录的修改可以完整追溯；
- 附件不能通过永久公开地址访问；
- AI 服务故障时核心记录流程仍可用；
- 数据可从备份恢复，聚合视图可从流水重建；
- 仓库和构建产物中不存在真实 Secret；
- 示例配置只包含占位符和 Secret 引用；
- 单机环境至少使用仓库外受限目录；
- 多节点环境使用远程加密 Secret Store；
- 服务只获得自身需要的最小 Secret 集合；
- Secret 访问、版本、轮换和撤销可以审计；
- 日志、错误和监控不会泄露 Secret；
- 关键 Secret 缺失或权限错误时系统安全失败；
- Secret 可安全轮换且不会造成不可恢复的多节点不一致；
- 未经明确配置不会跨区域或跨境复制 Secret；
- 泄露事件有撤销、轮换、审计和修复流程。
