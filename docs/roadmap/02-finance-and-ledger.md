# 资金、礼金与结算

## 1. 目标

建立一套能表达多人、多账户、多支付方式、多次转交和多种结算性质的资金模型，同时避免把内部流转重复计算为收入或支出。

## 2. 核心难点

- 礼金归属人与实际付款人不同；
- 一笔转账对应多人或多个家庭；
- 同一笔钱经过代收、转交、换现和现金交接；
- 活动资金分散在多个个人账户和现金箱；
- 采购人先垫付，后续可能部分报销或合并报销；
- 订金、尾款、押金、退款和余款性质不同；
- 银行流水、截图和人工记录可能重复；
- 实际盘点与系统理论余额可能不一致。

## 3. 资金位置模型

每笔资金必须位于一个可识别的位置：

- 银行账户；
- 微信、支付宝等支付账户；
- 现场现金箱；
- 某个成员临时保管；
- 采购人个人账户中的垫付款；
- 商家占用的订金或押金；
- 在途转账；
- 未确认位置。

建议维护：

- 位置名称和类型；
- 归属人或管理人；
- 是否属于活动资金；
- 是否可用；
- 理论余额；
- 最近盘点余额；
- 数据可见范围。

## 4. 交易性质

### 外部收入

资金从活动外部进入活动体系，例如礼金、赞助、补贴和退款。

### 对外支出

资金从活动体系流向外部商家、人员或机构，并形成真实成本。

### 内部转移

资金在活动内部不同位置之间移动，不影响净收入和净支出。

包括：

- 账户间转账；
- 提现；
- 换现；
- 现金交接；
- 资金归集；
- 备用金发放；
- 余款交回。

### 个人垫付

付款发生在个人资金位置，但经济责任属于活动。系统需同时形成：

- 对外支出；
- 活动对垫付人的待偿义务。

### 报销

活动资金支付给垫付人，用于结清待偿义务。报销不是新的活动成本。

### 订金、押金和尾款

- 订金通常属于订单预付款；
- 押金属于可退回资金，不应直接计为成本；
- 尾款用于结清订单应付；
- 押金扣除后，扣除部分才可能转为真实成本；
- 退款应关联原付款或订单。

## 5. 礼金双账模型

### 礼金归属账

回答谁表达了礼金，以及礼金应归属于哪个人、家庭、单位或关系主体。

### 实际资金账

回答谁实际付款、通过什么方式、谁代收、钱进入哪个位置，以及是否再次转交。

两者通过分配关系连接：

- 一笔付款可以分配给多个礼金主体；
- 一个礼金主体可以由多笔付款组成；
- 分配金额总和应与已确认付款金额一致，差异进入待确认；
- 未知付款人或未知归属允许暂存。

## 6. 关键流程

### 收款

1. 记录实际收款；
2. 识别支付方式和到账位置；
3. 填写或稍后补充付款人；
4. 关联礼金归属主体；
5. 若为合并转账，拆分分配；
6. 确认并进入资金位置余额。

### 现金交接

1. 选择来源现金箱或保管人；
2. 选择接收人或目标现金箱；
3. 输入金额；
4. 双方可分别确认；
5. 来源减少、目标增加；
6. 未确认交接进入待办。

### 备用金

1. 从活动资金位置发放；
2. 指定领款人和用途；
3. 关联后续支出、转交和余款退回；
4. 计算未交账余额；
5. 完成核销。

### 垫付与报销

1. 记录个人付款和用途；
2. 建立待报销余额；
3. 可关联多个费用明细；
4. 支持部分报销；
5. 报销完成后结清余额；
6. 防止重复报销。

### 盘点与对账

1. 选择资金位置；
2. 展示理论余额；
3. 录入实际余额；
4. 生成差异；
5. 要求说明、补记或更正；
6. 保留盘点历史。

## 7. 风险与异常检查

- 同一交易号或相同截图重复录入；
- 相同金额、时间和双方的疑似重复交易；
- 报销金额超过待报销余额；
- 备用金长期未交账；
- 押金长期未退款；
- 退款没有关联原付款；
- 内部转移只有单边记录；
- 现金交接一方未确认；
- 资金位置出现无解释负余额；
- 盘点差异超过阈值；
- 合并礼金尚未完成归属分配。

## 8. 管理视图

- 总收入、总支出和净结余；
- 各资金位置余额；
- 礼金归属清单；
- 未确认收款；
- 未拆分合并款项；
- 垫付与报销清单；
- 备用金未交账清单；
- 商家应付、押金和退款清单；
- 现金盘点差异；
- 按人员、商家、类别和阶段统计。

## 9. 开发计划

### P0：模型与规则

- 定义资金位置和交易性质；
- 定义礼金归属与付款分配模型；
- 定义金额精度、币种和舍入规则；
- 建立内部转移双边记账规则；
- 建立垫付、报销、备用金和押金状态机。

### P1：资金 MVP

- 创建和管理资金位置；
- 收入、支出和内部转移；
- 现金交接；
- 个人垫付和部分报销；
- 备用金与余款退回；
- 理论余额和基础对账；
- 附件和修改历史。

### P2：礼金与结算

- 礼金归属主体；
- 合并付款拆分；
- 商家订金、尾款和押金；
- 退款匹配；
- 盘点差异处理；
- 自动异常检查。

### P3：自动匹配与导入

- 支付截图识别；
- 银行或支付流水导入；
- 重复记录识别；
- 自动推荐垫付与报销关联；
- 自动生成活动结算摘要。

## 10. 验收标准

- 内部转账、换现和现金交接不改变净收支；
- 能正确表达多人合并礼金和一人代付；
- 支持一笔垫付多次报销，以及一笔报销结算多笔垫付；
- 能计算每个资金位置的理论余额；
- 能列出全部未结清资金事项；
- 对重复报销、单边转移和押金未退给出明确提示；
- 所有关键资金修改均可追溯。
