# ChatGPT Work 交接与执行说明

## 1. 用途

本文档用于把 OccasionOps 从需求分析阶段平滑交接到 ChatGPT Work 中持续推进。

ChatGPT Work 负责：

- 持续整理需求与决策；
- 根据 roadmap 拆解工作包；
- 跟踪 GitHub Issues 和交付状态；
- 输出领域模型、原型说明、测试场景和验收报告；
- 在需要实现代码时，将明确的技术任务交给 Codex。

GitHub 继续作为事实来源，所有关键决策、开发任务和验收标准应最终回写仓库。

- 需求与开发计划：`docs/roadmap/`
- 当前阶段：需求验证、领域模型和 MVP 拆解

## 3. Work 首次进入时的推荐指令

在 ChatGPT 顶部切换到 **Work**，从保存 OccasionOps 上下文的同一个 Project 中启动新 Work 对话，然后粘贴：

```text
继续推进 GitHub 仓库 Ltre/occasion-ops。

以 dev/2607C-newcode 分支的 docs/roadmap 为需求与开发计划事实来源。
优先阅读：
- docs/roadmap/README.md
- docs/roadmap/00-product-scope.md
- docs/roadmap/01-domain-model.md
- docs/roadmap/08-delivery-plan.md
- docs/roadmap/09-open-questions.md
- docs/roadmap/10-chatgpt-work-handoff.md

工作规则：
1. 不修改根 README，除非我明确要求；
2. 先完成 P0 领域验证和平台基础，再进入资金与物料开发；
3. 每项工作必须关联 GitHub Issue；
4. 每个 Issue 必须包含背景、范围、非目标、验收标准和依赖；
5. 需求或规则发生变化时，先更新 docs/roadmap，再安排代码实现；
6. 涉及代码、测试、数据库迁移和仓库命令时，形成清晰技术任务并交给 Codex；
7. 不让 AI 自动确认高风险资金、礼金、库存或权限变更。

先检查当前开放 Issues 和 dev/2607C-newcode 相对 main 的差异，然后给出本次执行计划。
```

## 4. Work 与 Codex 的职责边界

### Work 更适合

- 需求研究与访谈整理；
- 路线图维护；
- 领域术语和业务规则定稿；
- 产品原型说明；
- 测试案例与验收清单；
- Issue 拆解和优先级调整；
- 阶段总结、风险清单和决策记录。

### Codex 更适合

- 建立项目代码骨架；
- 数据库、API 和前端实现；
- 编写单元测试、集成测试和迁移脚本；
- 运行命令、调试和修复 CI；
- 提交代码、推送分支和创建 PR。

## 5. 工作循环

每个工作包建议按以下循环推进：

1. **读取事实来源**：roadmap、相关 Issue、现有实现和历史决策；
2. **确认范围**：目标、非目标、依赖、风险和验收标准；
3. **产出设计**：流程、状态机、数据模型、接口或页面说明；
4. **拆解实现**：将可以编码的任务交给 Codex；
5. **验证结果**：场景回归、权限、幂等、一致性和可用性；
6. **回写仓库**：更新文档、Issue 状态和必要的 ADR；
7. **决定下一步**：进入下一工作包或回到需求验证。

## 6. 事实来源优先级

发生冲突时，按以下顺序处理：

1. 用户最新明确指令；
2. 已确认的 ADR 或 GitHub Issue 决策；
3. `docs/roadmap` 中的业务规则；
4. 根 README 的项目级介绍；
5. 代码中的历史行为。

若代码与已确认业务规则不一致，应先记录差异，再决定迁移或兼容策略，而不是默认为代码正确。

## 7. 每个 Issue 的完成定义

Issue 完成至少满足：

- 范围内验收标准全部通过；
- 关键边界和异常有测试；
- 权限和审计要求已覆盖；
- 新规则已写入相应 roadmap 或 ADR；
- 没有遗留未说明的数据迁移风险；
- 相关 PR、测试结果和演示说明已关联；
- 未完成事项已拆为新的 Issue，而不是隐藏在评论中。

## 8. 当前最优执行顺序

1. 领域术语、流水词典和状态词典；
2. 真实业务故事与场景测试集；
3. 活动、成员、角色和数据范围；
4. 统一流水、附件、关联、更正和审计；
5. 资源位置、幂等和并发版本；
6. 资金闭环；
7. 礼金、采购与物料闭环；
8. 现场快捷入口、临时用户和弱网；
9. AI 候选整理与闭环检查。

任何阶段均不应因为 AI 能力尚未完成而阻塞核心人工流程。
