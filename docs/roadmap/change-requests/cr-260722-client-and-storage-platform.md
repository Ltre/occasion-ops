## 变更摘要

首期客户端明确为 PWA 与微信小程序，Android/iOS 延后到资金 MVP 和真实试点稳定后再评估。

主要面向中国大陆用户的生产环境不应默认使用海外 S3。对象存储改为国内云优先、国际存储可选，并通过项目统一的存储 Provider 接口隔离阿里云 OSS、腾讯云 COS、AWS S3、Cloudflare R2 等实现。

## 原来的需求

- 既有技术文档将前端描述为“优先 PWA”；
- 微信小程序尚未被明确列为首期正式客户端；
- Android 与 iOS 的阶段没有明确；
- 服务端架构将附件存储笼统写成“S3 兼容对象存储”；
- 没有明确中国大陆与海外用户的存储区域选择；
- 没有明确厂商适配、数据驻留、迁移和跨境复制原则。

## 改动后的需求

### 客户端

- 首期同时实现 PWA 与微信小程序；
- 两端共同支持初代资金流水核心功能；
- 两端使用相同服务端 API、资金语义、权限、审计和测试标准；
- 领域类型、API 契约、校验、确认摘要和场景测试优先共享；
- 平台登录、本地存储、拍照、扫码、上传和通知使用适配层；
- Android/iOS 不阻塞 MVP，达到明确触发条件后再开发。

### 对象存储

- 中国大陆生产环境优先选择阿里云 OSS、腾讯云 COS 等国内对象存储；
- 海外部署保留 AWS S3、Cloudflare R2 或其他国际对象存储选择；
- 业务代码依赖项目自有 `ObjectStorageProvider`，不直接绑定厂商 SDK；
- 不假设国内厂商完整兼容 AWS S3；
- 附件默认私有，服务端鉴权后签发短期凭证；
- 一个部署环境必须有明确主数据区域；
- 不默认跨境复制；
- 迁移、复制和删除必须记录状态、审计和完整性校验。

## 变更原因

- 中国大陆用户更适合通过微信小程序快速进入现场系统；
- PWA 仍适合链接访问、管理端和海外用户；
- 初期同时开发 Android/iOS 会分散资金 MVP 的研发资源；
- 中国大陆访问海外存储的链路和体验不适合作为默认生产基线；
- 海外用户仍需要就近存储和良好访问体验；
- 单一厂商绑定会增加迁移、区域扩展和长期运维风险。

## 影响分析

### 产品与交互

- 首期产品测试需要同时覆盖 PWA 与微信小程序；
- 核心功能保持一致，但 UI 和平台能力不要求像素级一致；
- 临时用户入口优先考虑 Web 链接、二维码和微信小程序。

### 领域与数据

- 资金、权限和审计模型不因客户端而变化；
- 附件元数据需要记录存储配置、区域、对象键、哈希和状态；
- 同一个自然人的微信身份、手机号身份和临时身份需要可绑定和审计。

### API 与实现

- 需要共享 API 契约和跨端场景测试；
- 需要客户端平台适配接口；
- 需要对象存储 Provider 抽象及至少一个国内生产适配器；
- 需要短期上传／下载授权和幂等上传确认。

### 数据迁移与兼容

- 当前尚无生产附件数据，不需要立即迁移；
- 未来更换云厂商时必须按可恢复迁移流程执行；
- 不能把永久公网 URL 作为唯一附件引用。

### 测试与验收

- PWA 与微信小程序通过同一套核心资金场景；
- 国内与国际对象存储适配器通过统一契约测试；
- 验证弱网、重复提交、附件上传恢复、权限和短期凭证；
- 验证数据库恢复后附件仍可定位；
- 验证未配置时不会跨境复制。

### 进度与风险

- 首期客户端工作量增加为两个正式端，需要严格共享业务规则并控制 UI 重复开发；
- 同时接入多个生产存储不是首期目标，可先实现一个国内主适配器；
- 海外适配器首期可以先完成契约验证；
- 微信平台能力和浏览器能力差异需要明确降级策略。

## 建议如何修改

- 使用 Monorepo 共享领域类型、API 契约、校验和测试场景；
- PWA 与微信小程序分别维护平台壳和 UI；
- 创建 `ObjectStorageProvider` 及厂商适配器；
- 国内生产首期从 OSS 或 COS 中选择一个主提供者；
- 国际适配器优先验证 S3 或 R2；
- 在部署配置中明确区域、Provider 和数据驻留；
- 在 CI 中执行跨端契约测试和存储 Provider 契约测试。
