## 变更摘要

所有 API 配置、密钥、Token、密码、私钥和其他保密数据都不得保存到代码仓库中。

单机环境最低使用仓库外的有限权限目录或只读 Secret 挂载。多节点或远程服务环境必须进一步采用远程加密 Secret Store、最小权限工作负载身份和节点本地有限权限目录、内存或 `tmpfs` 的多级结构。

## 原来的需求

- 已有安全文档要求敏感字段加密、日志不记录完整敏感信息；
- 对象存储文档要求使用密钥引用，不保存明文密钥；
- 尚未建立覆盖所有 API Key、Token、密码、私钥和证书的统一 Secret 管理基线；
- 尚未明确仓库零秘密、单机受限目录、多节点远程加密存储、工作负载身份、轮换和泄露处置规则；
- 尚未明确 CI/CD、容器镜像、前端构建产物和测试记录不得携带真实 Secret。

## 改动后的需求

### 仓库零秘密

- 任何真实 Secret 不得进入源码、配置、文档、Issue、PR、日志、测试夹具、构建产物或 Git 历史；
- 仓库只保存配置 Schema、占位符和 Secret 引用；
- `.env.example` 等示例只能包含占位符；
- `.gitignore` 不是 Secret 管理方案，只是防误提交措施；
- 已提交的 Secret 必须立即撤销或轮换，不能只删除文件。

### 单机最低结构

- Secret 位于仓库和发布目录之外；
- 使用专用服务账号；
- 目录建议 `0700`，文件建议 `0400` 或 `0600`；
- 容器使用只读 Secret Mount；
- 可行时使用内存或 `tmpfs`；
- 不进入镜像、普通备份和日志。

### 多节点结构

- 使用远程加密 Secret Store；
- 由 KMS、HSM 或等价服务保护主密钥；
- 使用工作负载身份或短期引导凭证；
- 节点只获取当前服务需要的最小 Secret；
- 本地仅在内存、`tmpfs` 或只读受限目录短期落地；
- 支持版本、轮换、撤销、审计、告警和恢复；
- 不通过人工复制明文文件向多台服务器分发。

### 区域与跨境

- Secret 与部署区域和数据驻留策略一致；
- 中国大陆与海外环境可以使用相同逻辑引用名但不同实际值；
- 不默认跨区域或跨境复制 Secret；
- 跨区域同步必须经过明确评审、加密和审计。

### CI/CD 与运行时

- CI 使用平台 Secret Store 或短期工作负载身份；
- 不可信 PR 不注入生产 Secret；
- 前端、PWA、小程序和移动端构建产物不得包含服务端 Secret；
- 日志、错误、指标和追踪必须统一脱敏；
- 关键 Secret 缺失或权限错误时应用安全失败；
- 非关键第三方 Secret 缺失时可禁用对应功能，但不能影响核心资金手工记录。

## 变更原因

- Secret 一旦进入 Git 历史，删除文件无法消除泄露风险；
- 单机明文配置和多节点人工复制无法满足最小权限、轮换和审计；
- 项目将接入数据库、Redis、对象存储、微信平台、AI/OCR 和其他外部服务，需要统一的秘密管理方式；
- 未来国内与海外多区域部署需要区域隔离和可审计的 Secret 分发；
- 资金系统必须避免因密钥泄露造成数据读取、篡改、删除或外部费用风险。

## 影响分析

### 产品与交互

不改变终端业务功能。部分外部服务 Secret 缺失时，相关增强功能可明确降级，但核心资金手工记录仍须可用。

### 领域与数据

不保存 Secret 值到业务数据库。可以保存 Secret 引用、Provider、版本、用途和轮换元数据，但不得保存可直接使用的明文。

### API 与实现

- 需要定义 `SecretReference` 和 `SecretProvider`；
- 需要本地文件、远程 Secret Store 和测试 Provider；
- 需要配置加载、权限校验、缓存边界和安全失败逻辑；
- 需要统一日志脱敏和错误序列化；
- 不允许业务模块直接依赖某一家 Secret 管理厂商 SDK。

### 数据迁移与兼容

当前尚无生产 Secret 迁移。若发现历史仓库、镜像或部署目录中存在真实 Secret，必须按泄露事件处理并轮换。

### 测试与验收

需要验证：

- 仓库和构建产物 Secret 扫描；
- 示例配置没有真实值；
- 受限目录权限；
- 未授权服务无法读取；
- 多节点轮换；
- 日志和错误脱敏；
- 不可信 PR 不注入生产 Secret；
- 备份与恢复不产生明文副本；
- 未配置时不跨区域复制。

### 进度与风险

- 首期需先完成仓库扫描、配置分离、本地受限 Provider 和日志脱敏；
- 多节点生产前必须完成远程 Secret Store、工作负载身份、版本轮换和审计；
- 厂商选择可以后置，但项目接口和安全边界必须从第一版存在。

- 使用工作负载身份或短期凭证；
- 为 Secret 轮换、撤销、审计和事件处置创建实现任务。
